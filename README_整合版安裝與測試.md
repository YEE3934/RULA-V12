## 先看三件事

1. 此版本是完整 RULA 網頁（**不是** Angle Lab），保留原本姿勢估測、Table A/B/C、三視角同步、手腕 Hand、影片時段設定、骨架品質、人工補正與 ZIP 匯出。
2. 新增 **V12 跨視角研究**：逐張抽樣影格比較同一個**人體左手側／右手側**在不同攝影機的前臂、頸部 2D 代理角，並提供**研究試算 Grand Score**。**不會覆寫**原始正式 Grand Score、AL、人工修改或共享頸分。
3. V12 預設開啟。**Front 正面鏡頭角度只供診斷；絕不自動替換前臂屈伸或頸部前屈。** 原側面品質不佳、另一側側面即使通過初步門檻，也只能作為待驗證研究候選，不是準確角度保證。

## 方案A：最安全的 Streamlit Cloud 測試方式（推薦）

1. 在 GitHub 新開測試 repository，例如 `RULA-System-V12-Test`，不要覆蓋原本正式專案。也可使用舊專案的**獨立測試分支**再建立第二個 Streamlit App。
2. 解壓縮此 ZIP，將**內容中的所有資料夾與檔案**放在 repository 根目錄。**不能只上傳 `222.py`**，因為它需要 `angle_lab_core.py` 與 `rula_cross_view_bridge.py`。
3. 前往 Streamlit Community Cloud 建立 App，主程式選擇 **`222.py`**，Python 版本建議 **3.11**。
4. 觀察開頭部署識別應為 `RULA_222_CROSS_VIEW_V12_RESEARCH_2026-11-06`。如遇 MediaPipe、protobuf 套件衝突，請用 ZIP 內 `requirements.txt`，不要自行升級 mediapipe 至移除 `mp.solutions` 的新版。
5. 確認影片同步後進行分析。請在第一步開啟「**🧪 V12 跨視角角度研究**」，勾選「啟用每張抽樣影格的跨視角品質檢查」。

> 若選擇覆蓋正式 GitHub，請先備份原分支或建立 commit/tag，保留可回復版本。正式學校報告不建議直接使用未驗證的研究試算分數。

## 方案B：Windows 本機測試

建議 Python 3.11。在此 ZIP 根目錄執行：

```powershell

.venv\Scripts\activate
python -m pip install -r requirements.txt

```

若 Hand Landmarker 模型因網路限制下載失敗，既有正式流程會使用 Pose 2D 備援；這與 V12 研究檢查是不同功能。

## 如何試搬運、品檢、撿料

每個作業**個別進行**，不要把三種影片混為同一次三視角同步錄影。每次：

1. 上傳同一作業、同一位受測者的正面、左側、右側三支影片。若單側評估只上傳其中一支側面＋Front，V12 無法取得另一支側面的替代角度，但仍能診斷本側視角。
2. 確認三視角同步、影像是否被水平翻轉、姿勢及受測者左右手對應正確。
3. 抽樣數先設 **5～10 張**，確定部署及匯出正常後再設 25、30、50 等。**V12 只檢查實際抽樣的影格，不是全部影片影格。**
4. 啟動分析，進入結果頁 **「🧪 跨視角研究」**，按樣本編號查看 Left／Front／Right 候選。
5. 看到「研究候選：另一側鏡頭（待人工驗證）」時，表示**人體側別不變**，只是從另一支攝影機估同一隻手；不要直接把候選角當正式真值。
6. 看到「無合格側向視角」、「頸部跨鏡頭分歧」或「跨側頸角重大分歧」時，請開三視角原始影格人工確認。**沒有候選角度不是 0°，不能當成零誤差。**
7. 在 **「📦 下載」** 下載整合 ZIP，查看下面新增的 CSV。

## 新增輸出在哪裡？

使用網頁最終「📦 下載」取得的 ZIP：

- `技術診斷/V12_Cross_View_Summary.csv`：每個樣本、人體側別、前臂及頸部的選擇結果與原因。
- `技術診斷/V12_Cross_View_All_Candidates.csv`：各視角的所有候選角度、關鍵點可見度、投影品質、`eligible` 和警告。
- `技術診斷/V12_Research_Score_Comparison.csv`：**最重要**。同一筆樣本的正式 Grand Score、前臂實際採用角度、研究候選角、研究試算分數及差異。
- `技術診斷/V12_Readme.txt`：演算法規則及限制。
- `原始分析/`、`複核後結果/`：既有評分結果，不由 V12 候選角度覆寫。
- `Raw_Frames/`、`Photos/` 等照片資料夾（取決於原設定是否勾選原始影像匯出）供查看原畫面。

**注意**：直接分析時程式建立的原始 ZIP 裡是 `Diagnostics/...`，最終下載由原本報表整合流程將其歸類為 `技術診斷/...`。請以實際下載 ZIP 內路徑為準。

## 四個重要的研究限制

1. 2D 視角品質門檻屬工程探索，**不是**攝影機幾何校正或量測誤差的可信區間。
2. 左側攝影機與「人體左側」不同；V12 固定人體側別，左肩／肘／腕 = 11／13／15，右肩／肘／腕 = 12／14／16。**請確認影片無鏡像**。
3. 前臂角度與舊正式 `222.py` 定義一致：`180°－肘內角`。人工若用量角器量肘內角（例如 100°），比較時須先換算成屈曲代理角（80°）。頸部耳肩髖只是 2D 姿勢代理角，不能直接當作真實頸椎屈曲角度。
4. 沒有可靠候選時，**正式 RULA 分數仍維持原本程式產生的初步結果**，V12 只顯示警告或研究試算缺值；正式是否採信須依原本品質審核／人工覆核決定。此版並不會自動把不可靠的正式分數刪除。

## 驗收清單

- [ ] 使用原本的 `222.py` 不變版本成功分析同樣影片，留下一份基準 ZIP。
- [ ] 新版上傳三視角、同步、啟動分析正常；每張抽樣影格都有 V12 研究列。
- [ ] 人體左側候選只使用左肩(11)、左肘(13)、左腕(15)，即使來源是 Right 攝影機。
- [ ] Front 前臂品質即使 0.99，也不被選為正式側面屈伸角替代來源。
- [ ] 同時間左右側頸角分歧能出現研究警示；不會把兩側角度直接平均。
- [ ] `V12_Research_Score_Comparison.csv` 存在，且原始正式分數／人工覆核結果保留。
- [ ] 搬運、品檢、撿料各至少 5 張測試，確認沒有出現大量不合理空值或左右手顛倒。
- [ ] 正式比較 MAE 時，只在**相同影片、相同秒數、相同人體側別、相同角度定義**的配對樣本上計算。
